# OPP-0104: External Calendar Bridge (ICS/CalDAV) with Prayer Shield

## 1. Problem Statement
Knowledge workers use Google Calendar, Outlook, or Apple Calendar for their work schedules. Because Midmar LifeOS operates offline, users experience scheduling collisions where corporate meetings overlap with prayer times or sacred circadian focus blocks.

## 2. Evidence Base
- Station `WORK_MICRO_SPRINT` and `EVENING_SPRINT` manage task blocks, but have no visibility into corporate calendar commitments.
- Users are forced to switch between their calendar app and Midmar repeatedly throughout the workday.

## 3. Counter-Evidence & Risks
- Implementing Google/Microsoft OAuth requires registering client IDs, maintaining cloud secrets, and ongoing token refreshes, violating pure local-first zero-telemetry principles.
- Parsing full iCalendar (RFC 5545) recurrence rules is notoriously edge-case heavy.

## 4. Alternatives Considered
- **Alternative A (Zero-Cloud ICS Feed URL):** User provides a secret read-only `.ics` subscription link (or imports an `.ics` file). The browser fetches the feed, parses VEVENT records locally, and displays busy blocks without storing third-party tokens.
- **Alternative B (Full Bi-directional Google Calendar API):** Requires third-party cloud authentication and privacy compromise.

## 5. Technical Architecture
1. Local ICS parser (`ical.js` or lightweight regex parser).
2. Store calendar events in Dexie `externalCalendarEvents` table.
3. Overlay events on the Circadian Aurora Timeline.
4. "Prayer Shield" feature: Automatically marks prayer windows (+/- 15 minutes around Adhan) as protected, suggesting optimal sprint focus blocks outside those windows.

## 6. Success Metrics
- Zero external server auth infrastructure required.
- Visual display of external events on the Circadian Timeline in <100ms.
