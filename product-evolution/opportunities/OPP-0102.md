# OPP-0102: In-Browser WebAssembly Quran Recitation & Tajweed Helper

## 1. Problem Statement
Users reciting Quran during morning commute or evening sprint lack real-time feedback on verse progression or pronunciation accuracy. Competitors like Tarteel require continuous cloud streaming, compromising privacy and failing in low-connectivity areas.

## 2. Evidence Base
- Station `RETROSPECTIVE_CHECKIN` and `HOME` contain Quran trackers, but progression relies entirely on manual verse clicking.
- User desire for sovereign, offline-first spiritual companion.

## 3. Counter-Evidence & Risks
- Running speech models in the browser via WebAssembly/ONNX can consume substantial memory (~50-100MB model weights) and drain mobile batteries.
- Browser audio permissions can be fragile on iOS Safari.

## 4. Alternatives Considered
- **Alternative A:** On-device quantized Whisper WASM / ONNX model loaded on-demand only when entering the Quran station.
- **Alternative B:** Simple microphone audio level detection (voice activity detection) that auto-scrolls verses based on cadence rather than phonetic matching.

## 5. Technical Architecture
1. Package a compact quantized acoustic model via `@xenova/transformers` with WebGPU/WASM backend.
2. Load model assets lazily into CacheStorage on first user consent.
3. Compare recognized Arabic phonemes against `src/data/quranSurahData.ts` verse strings with Levenshtein fuzzy matching.

## 6. Success Metrics
- Word recognition accuracy > 88% on standard recitation.
- Zero audio bytes transmitted over the network (100% offline sovereignty).
